## 三、P0：必须先修，否则核心体验不成立

### P0-1　填空模式对 60.6% 的单词彻底不可用（按钮永久置灰，无任何提示）

- 位置：`frontend/src/App.vue:21`（`resetCloze`）与 `frontend/src/App.vue:16`（`revealCount`）
- 现象：`resetCloze` 里用的是 `Math.floor(char.length / 3)`，`char` 是单个字符，长度恒为 1 → **只把第 0 位预填了字**；而模板按 `revealCount = floor(单词长度/3)` 决定"前几位算已给出"。长度 ≥6 的单词 `revealCount ≥ 2`，第 1 位被渲染成既有字母（无输入框），`clozeAnswer[1]` 永远是空字符串。
- 后果链：`clozeAnswer.some(char => !char.trim())` 恒为真 → **「检查答案」按钮永远 disabled**，`@keyup.enter` 也在 `submitCloze` 开头 return。用户把能填的都填了，按钮还是灰的，点不动、也没提示，只能切回卡片模式。
- 即使跳过按钮直接提交，`join('')` 也会漏掉被隐藏的那一位 → **永远判错**；判错后 `continueCloze` 记 `again`，`interval=0` → 这个词立刻又变成"待复习"，下次进来继续卡住，形成死循环。
- 影响面：5000 词表里 **3029 / 5000（60.6%）** 的单词长度 ≥6；再加上含空格/连字符的 20 个词，实际受影响更多。
- 修复：`resetCloze` 与模板统一走同一个 `revealCount`（`spelling.length`，不是 `char.length`）；`clozeAnswer` 只在真正有输入框的位上取值；提交时按位比较、忽略大小写；对空格/连字符单独处理（直接显示、不需要输入）。

### P0-2　个人导入的词典对所有用户可见（数据泄露）

- 位置：`backend/vocabulary/views.py:268`（`import_personal_dictionary` 里 `status='published'`，且 `Dictionary` 没有 owner 字段）
- 实测：用户 alice 导入「Alice private」后，用户 bob 调 `/api/dictionaries/` 拿到 `['Audit dict', 'Alice private']`，并且能 enroll、能背。
- 影响：任何人上传的文件都会变成"全站公开词典"，既是隐私问题，也会让词典列表被别人的导入刷屏；同名重复导入还会不断堆积（实测同名导入 3 次 → 库里 3 本同名词典）。
- 修复：`Dictionary` 增加 `owner`（可空，空=官方词典）与 `visibility`（public/personal）；个人词典 `status='draft'` 或 `visibility='personal'`，列表接口按 `owner=user OR owner is null` 过滤；同名导入做 upsert 或拒绝。

### P0-3　Docker 发布链路启动即失败

- 位置：`backend/vocabulary/management/commands/seed_demo.py:21` + `backend/Dockerfile:6`
- 现象：`seed_demo` 用 `Path(__file__).resolve().parents[4] / 'data' / 'samples' / 'words.csv'`。本地仓库结构下正好是仓库根目录，能跑；但镜像里后端代码被拷到 `/app`，同一行解析出来是 `/data/samples/words.csv`——**镜像里没有这个文件**（`COPY . .` 只拷了 `backend/`，`data/` 根本不在构建上下文里）。
- 后果：`CMD ["sh","-c","python manage.py migrate && python manage.py seed_demo && ..."]` 在第二步抛 `FileNotFoundError`，`&&` 链中断，容器退出。README 里写的 `docker compose up --build` 拿不到可用服务。
- 附带问题：`docker-compose.yml` 里 `./backend:/app` 的 volume 还会把镜像内容盖掉；`DJANGO_DEBUG=0` 下用 `runserver`，`/admin/` 静态资源也不会被服务（没有 `collectstatic`/whitenoise），后台是无样式的。
- 修复：把 `data/samples` 拷进镜像（或把示例词表放进 `backend/vocabulary/fixtures/`），`seed_demo` 用相对 `BASE_DIR` 的路径；发布用 gunicorn + whitenoise（或 nginx 托管 static）；去掉代码 volume 挂载。
- 备注：本机没有安装 Docker，以上按代码路径推断，未实测。

### P0-4　`index.html` 是 HTML 碎片

- 位置：`frontend/index.html`（全文只有两行：一个 div + 一个 script）
- 缺 `<!DOCTYPE html>`、`<html lang="zh-CN">`、`<head>`、`<meta charset>`、`<meta name="viewport">`、`<title>`。
- 后果：浏览器进 quirks mode，盒模型/字体渲染与预期不一致；**没有 viewport，手机上整站按 980px 缩放**，字体小到看不清；标签页标题显示 URL；构建产物 `frontend/dist/index.html` 同样是碎片。
- 修复：补标准 HTML5 骨架 + viewport + 标题 + favicon；构建后核对 `dist/index.html`。

### P0-5　「今日任务 20 个」不是每日上限

- 位置：`backend/vocabulary/views.py:22`、`:120`
- 现象：`NEW_WORD_LIMIT = 20` 只是**每次请求**返回 20 个新词；答完这 20 个，它们进入 `UserWordProgress` 被 `exclude` 掉，再请求一次就返回**下一批** 20 个。实测同一会话内先拿 20 个、答完后立刻又拿到 10 个（词表只剩 30）。
- 后果：标题写着「今日任务」，实际可以无限刷；那个 20 既不是每日目标也不是每轮上限，统计口径（`completed_today`）和用户认知都对不上。
- 修复：按"今日已学新词数"扣减（`last_review_at__date = today` 且首次学习），或记录 `first_learned_at` 单独计数；前端显示"今日新词 x/20"并允许配置目标。

### P0-6　复习算法不成立：一次「记住了」就算掌握，间隔永远 3 天

- 位置：`backend/vocabulary/views.py:24`、`:161-168`
- 实测：同一个词连续 5 次 `good`，返回的 `interval_days` 都是 3，`status` 第一次就变 `mastered`。
- 后果：
  - 没有间隔递增，所谓"记忆曲线"只是固定的 0/1/3/7 天，复习量不会收敛；
  - 一次答对即"已掌握"，`mastered_words` 和 `progress_percent` 严重虚高（做完 20 个词就接近"掌握"）；
  - `again` 的 `next_review_at = now`，答完立刻又是 due，done 页的「待复习」数字会立刻飙上去。
- 修复：标准 SM-2 或简化版：`interval = interval * ease`，`review_count` 参与计算，`again` 重置到 0 并设定下次在 10 分钟后（或本轮重排），`mastered` 需要连续 N 次 good/easy 且间隔 ≥ 阈值；`due_reviews` 排除"刚刚答过"的词。

## 四、P1：页面交互逻辑

1. **学习页出不去**：进入 `view === 'study'` 后没有任何返回/退出按钮，只能刷新页面或背完。刷新会丢掉选中的词典和队列，直接回到词典列表。
2. **浏览器返回键 = 退出应用**：没有 vue-router，四个视图是手写状态机，地址栏永远是 `/`。刷新回到第一步，无法分享"某本词典的学习页"，也无法 deep-link。
3. **无键盘操作**：卡片模式看答案只有鼠标点「显示答案」，评分四个按钮也只能点。背 40 个词全靠鼠标，效率很低。空格看答案、1–4 评分是这类产品的标配。
4. **误点无法撤销**：评分按钮点下即提交并翻页，点错没有回退。
5. **评分没有间隔反馈**：按钮上不显示"1 天 / 3 天 / 7 天"，用户不知道自己选的东西意味着什么。
6. **错误文案英文直出**：后端返回 `invalid credentials`、`enroll in this dictionary first`、`file must contain word and meaning columns`、`authentication required`，前端原样展示。
7. **错误横幅跨页残留**：`errorMessage` 只在少数操作开始时清空，切到别的视图后还在。
8. **会话过期不回登录页**：任何接口 401 只显示一条英文错误，用户卡在死页面上。
9. **点卡片即 enroll**：`selectDictionary` 第一件事就是 `api.enroll`，用户只是想看看词表也会产生一条学习记录；卡片上还看不到进度（只显示总词数），无法判断哪本在学、学到哪了。
10. **模式/顺序不持久化**：刷新后 mode 回卡片、order 回字母序；`order` 只在进入词典时生效，改了不重排。
11. **长单词溢出**：`h3` 桌面 54px、移动 42px，最长的 `telecommunications`（18 字母）在 360px 屏会横向溢出卡片；填空模式 18 个 40px 输入框 ≈ 792px，直接撑破容器。CSS 里没有 `overflow-wrap`/自适应字号。
12. **空词典体验**：词表为空时进入直接跳 `done`，显示"今天的学习完成了 0 个单词" + 一排 0，没有"这本词典还没有单词"的空状态。
13. **加载态太弱**：只有 `disabled` + 文案变化，没有 skeleton/spinner；导 5000 词时页面看起来像卡死。
14. **无发音**：`Word.audio_url`、`pronunciation_url` 导进来了却从不播放，音标只是个静态文本。对背单词产品这是核心功能缺失。

## 五、P1：页面功能实现

1. **题型太少**：只有「卡片」和「填空」两种，没有看词选义、听音选词、拼写听写、例句挖空——而这些是同类产品的常见组合。
2. **没有错词本**：`wrong_count` 在攒，但没有"只练错词"的入口，也没有复习队列页。
3. **没有学习历史/连续天数/每日目标**：`UserWordProgress` 只保留最新状态，没有答题日志，未来做曲线/统计都没数据。
4. **词性没展示**：`part_of_speech` 存了但卡片上从不显示。
5. **无单词表浏览/搜索**：5000 词只能在背词时一个个看，不能查、不能跳。
6. **个人词典不可管理**：不能改名、删除、取消学习；导入错了只能留在列表里。
7. **前端有死代码**：`api.importDictionary`、`importDictionaryId`、`uploadDictionary` 全都没被调用（管理端导入只有 API，没有界面），`Word.cloze` 字段前端也没用。
8. **done 页信息太少**：只有本次完成数 + 三个数字，没有"下次复习时间""本词典进度条""再学一轮/去复习"的分流。

## 六、P1：数据与导入

1. **逐行写库**：5000 词走 5000 次 `update_or_create`（约 1 万条 SQL）。本地跑得动，nginx 默认 `proxy_read_timeout 60s` 下大概率 504——而 `data/imports` 里正好是 3500/5000 词的文件。
2. **JSON 格式异常直接 500**：`parse_import_rows` 只捕获 `ValueError/UnicodeDecodeError/JSONDecodeError`，传 `["a","b"]` 时 `rows[0].keys()` 抛 `AttributeError`（实测）。应校验元素是对象。
3. **大小写重复词**：`Abandon` / `abandon` / `ABANDON` 三行会全部入库（实测 `created=3`），唯一约束是区分大小写的。
4. **GBK CSV 不能导**：只按 `utf-8-sig` 解码，报 `'utf-8' codec can't decode byte`，提示对普通用户不可读；中文词表用 GBK/GB18030 很常见。
5. **个人导入无原子性、无上限**：不是 `transaction.atomic()`，中途异常会留下空词典；没有文件大小/行数限制，整个文件读进内存。
6. **重复导入无幂等**：同名导入每次都新建一本（实测 3 次 → 3 本），且全部 published。
7. **导入缺少进度反馈**：没有返回逐行错误摘要（管理端有 `errors` 但前端没展示），用户不知道哪几行被跳过。

## 七、P1：管理与发布

1. **Admin 不可用**：`admin.py` 只有一行 `admin.site.register([...])`，`Word` 没有 `list_display`/`search_fields`/`list_filter`。5000 词的后台是一页页翻，基本没法维护。
2. **管理端导入没有入口**：只有 `POST /api/admin/dictionaries/import`，前端没有上传界面，运营只能靠 curl。
3. **无发布流**：`seed_demo` 只创建草稿，没有"导入 → 校验 → 发布"的流程界面，也没有发布前检查（空词典、重复词、缺释义）。
4. **安全配置偏演示**：`CORS_ALLOW_ALL_ORIGINS = True` + `CORS_ALLOW_CREDENTIALS = True`；`SECRET_KEY` 有硬编码兜底；`DEBUG` 默认开；`AUTH_PASSWORD_VALIDATORS = []`；登录/注册没有任何限流（可暴力撞库）；`SESSION_COOKIE_SECURE`/`CSRF_COOKIE_HTTPONLY`/`SameSite` 未配置。
5. **无索引**：`UserWordProgress` 上没有 `(user, next_review_at)` 索引，复习/统计查询随数据量线性变慢。

## 八、P2：工程质量

1. **没有 git 仓库**：`fatal: not a git repository`。没有历史、没有 diff、改坏了回不去——这是目前最影响后续调整的一条。
2. **没有 tsconfig.json**：装了 `typescript` 却没有配置，`build` 只跑 `vite build`，**类型错误完全不拦**；也没有 `vue-tsc`。
3. **没有 lint/format**：无 ESLint、Prettier、stylelint。
4. **没有前端测试、没有 E2E**：后端只有 4 个用例，导入边界、复习调度、权限都没覆盖。
5. **前端是单文件巨石**：`App.vue` 44 行里塞了视图状态机、API 调用、导入 UI、填空逻辑、样式类名；没有组件、composable、store。改一处容易碰坏另一处。
6. **后端也是单文件**：`views.py` 278 行，且大量"一行塞多句"的写法（`d = ...; if not d: return ...`），可读性差，建议拆 `services.py`/`serializers` + 函数级视图。
7. **`.env` 是个 Python venv 目录**：和 README/`.env.example` 里的"配置文件 `.env`"直接冲突；docker compose 默认会把根目录 `.env` 当 env 文件读，遇到目录很可能直接报错（本机无 Docker 未实测）。建议改名 `.venv` 并更新 README。
8. **仓库冗余**：`data/sources/definitions.full.json` 与 `definitions.json` 内容完全相同（SHA256 一致），780KB 存了两份；`frontend/dist` 构建产物还留在工作区。
9. **`docs/` 是空目录**：没有 API 文档、部署文档、数据结构说明。
10. **开箱即空**：`seed_demo` 的示例词典只有 **2 个词**，3500/5000 只建了空壳草稿，而 `data/imports` 里现成 CSV 就在旁边。本地库里是我手动导过的，换台机器注册进去只有 2 个词可背。
11. **无依赖锁定/无 CI**：`requirements.txt` 只有区间，没有 `pip-compile`/`uv.lock`；没有 CI 跑测试。
12. **发布用 runserver**：没有 gunicorn/uvicorn，单进程开发服务器上生产。
